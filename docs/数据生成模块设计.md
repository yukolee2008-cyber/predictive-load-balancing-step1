# 数据生成模块设计

- **模块名称**: 数据生成模块 (Data Generation Module)
- **核心类**: `TrafficDataGenerator`
- **配置文件**: `config/config_data.yaml`
- **脚本入口**: `scripts/generate_data.py`

---

## 1. 概述

### 1.1 目标

数据生成模块的主要目标是生成符合真实网络流量模式的**合成时空流量数据**，用于：
1. **LSTM/Transformer 模型训练**：提供带时间特征的负载序列
2. **负载均衡策略仿真**：驱动网络仿真环境，验证不同策略的效果
3. **可控实验**：支持不同日期类型（工作日、节假日、周末等）的流量模式

### 1.2 数据特征

生成的数据具有以下特征：
- **时间序列性**：连续的时间戳序列，固定时间间隔（默认5分钟）
- **多基站**：支持多个基站（默认3个：gnb_0, gnb_1, gnb_2）
- **负载范围**：
  - **required_load**：需求负载，范围 [0.0, 1.2]
  - **正常场景**：[0.0, 1.0]（基站可承载）
  - **超载场景**：(1.0, 1.2]（除夕/春节等极端高峰）
- **日期感知**：7种日期档位（date_profile），模拟不同类型日期的流量模式
- **时段感知**：基于2小时粒度的时段配置（0-1, 2-3, ..., 22-23）

## 3. 配置系统

### 3.1 配置文件结构 (`config_data.yaml`)

#### 3.1.1 全局配置 (global)

```yaml
global:
  seed: 42                          # 随机种子（可复现）
  start_date: "2025-01-01"         # 起始日期
  num_days: 90                      # 生成天数
  time_interval_minutes: 5          # 时间间隔（分钟）
  
  output:
    format: csv                     # 输出格式
    path: data/                     # 输出路径
    filename_prefix: raw_traffic    # 文件名前缀
    
  network:
    n_gnbs: 3                       # 基站数量
```

#### 3.1.2 日期档位配置 (date_profiles)

定义了**7种日期类型**，每种类型使用**2小时粒度**的时段配置：

| 日期档位 | 名称 | 说明 | 典型特征 |
|---------|------|------|---------|
| 1 | `lunar_eve` | 除夕 | 下午至晚上负载极高，跨年夜特殊 |
| 2 | `spring_festival` | 春节 | 凌晨高活跃，白天拜年，晚上聚会 |
| 3 | `major_holiday` | 重大节假日 | 全天负载较高，有明显高峰 |
| 4 | `other_holiday` | 其他节假日/周末 | 无通勤高峰，休闲模式 |
| 5 | `pre_holiday` | 节假日前一天 | 晚上和深夜负载更高 |
| 6 | `normal_friday` | 普通周五 | 晚上负载比工作日高 |
| 7 | `normal_weekday` | 普通工作日 | 早晚高峰明显，午间小高峰 |

**时段配置示例**（以 `normal_weekday` 为例）：

```yaml
normal_weekday:
  description: "普通工作日（周一-周四）- 早晚高峰明显"
  enabled: true
  
  hour_segments:
    "0-1":   {center: 0.08, max: 0.15}   # 深夜低负载
    "2-3":   {center: 0.06, max: 0.12}   # 凌晨最低
    "4-5":   {center: 0.07, max: 0.14}
    "6-7":   {center: 0.15, max: 0.30}   # 早高峰开始
    "8-9":   {center: 0.45, max: 0.65}   # 上午工作高峰
    "10-11": {center: 0.40, max: 0.60}
    "12-13": {center: 0.35, max: 0.55}   # 午间小高峰
    "14-15": {center: 0.38, max: 0.58}
    "16-17": {center: 0.42, max: 0.62}
    "18-19": {center: 0.50, max: 0.70}   # 晚高峰
    "20-21": {center: 0.40, max: 0.60}
    "22-23": {center: 0.20, max: 0.35}   # 逐渐休息
```

**参数说明**：
- `center`：时段内负载的**期望中心值**
- `max`：时段内负载的**最大值**（required_load，可超过1.0）
- 实际生成时，在 `[center, max]` 范围内使用 Beta 分布采样

**超载场景设计** ⭐：

本设计中的 `load` 值代表 **required_load**（需求负载），而非基站实际可承载容量：

| 负载范围 | 场景类型 | 典型时段 | 说明 |
|---------|---------|---------|------|
| 0.0 - 1.0 | 正常场景 | 大部分时段 | 基站可完全承载 |
| 1.0 - 1.2 | 超载场景 | 除夕18-23点、春节0-1点 | 需求超过基站容量，会产生丢包 |

**超载时段配置示例**：
```yaml
lunar_eve:  # 除夕
  hour_segments:
    "18-19": {center: 0.95, max: 1.15}  # 年夜饭高峰（超载）
    "20-21": {center: 1.00, max: 1.20}  # 看春晚/守岁（极端峰值）
    "22-23": {center: 0.95, max: 1.10}  # 守岁活动（超载）

spring_festival:  # 春节
  hour_segments:
    "0-1": {center: 0.90, max: 1.10}    # 跨年祝福高峰（超载）
```

#### 3.1.3 日期映射规则 (date_mapping)

定义如何将具体日期映射到7种日期档位：

### 4.2 核心方法详解

#### 4.2.1 `generate()` - 主生成方法

```python
def generate(self) -> pd.DataFrame:
    """生成完整的流量数据"""
    # 1. 生成时间戳序列
    timestamps = self._generate_timestamps(...)
    
    # 2. 为每个基站生成负载
    gnb_loads = []
    for gnb_id in range(n_gnbs):
        loads = self._generate_gnb_loads(timestamps, gnb_id)
        gnb_loads.append(loads)
    
    # 3. 构建 DataFrame
    df = pd.DataFrame({
        'timestamp': timestamps,
        'gnb_0_load': gnb_loads[0],
        'gnb_1_load': gnb_loads[1],
        'gnb_2_load': gnb_loads[2]
    })
    
    # 4. 数据验证
    self._validate_data(df)
    
    return df
```

#### 4.2.2 `_generate_gnb_loads()` - 单基站负载生成

这是核心的负载生成逻辑：

```python
def _generate_gnb_loads(self, timestamps: List[datetime], gnb_id: int) -> np.ndarray:
    """为单个基站生成负载序列"""
    loads = np.zeros(len(timestamps))
    
    for i, ts in enumerate(timestamps):
        # 步骤1：识别日期类型
        if ts.date() != current_date:
            current_date = ts.date()
            profile_name = self.date_detector.get_date_profile(current_date)
            current_profile = self.config_parser.get_profile(profile_name)
        
        # 步骤2：获取当前小时的负载配置
        hour = ts.hour
        load_config = current_profile.get_load_for_hour(hour)
        center = load_config['center']
        max_val = load_config['max']
        
        # 步骤3：Beta 分布采样（偏向 center 值）
        alpha, beta = 2.0, 5.0
        random_factor = np.random.beta(alpha, beta)
        load = center + (max_val - center) * random_factor
        
        # 步骤4：添加小量噪声
        noise = np.random.normal(0, 0.02)
        load = np.clip(load + noise, 0.0, 1.0)
        
        loads[i] = load
    
    # 步骤5：平滑处理
    loads = self._smooth_loads(loads, timestamps)
    
    # 步骤6：基站差异化
    loads = self._apply_gnb_variation(loads, gnb_id)
    
    return loads
```

**关键点**：
1. **时段映射**：每个小时被映射到一个2小时时段（如 0→"0-1", 2→"2-3"）
2. **Beta 分布**：参数 `alpha=2.0, beta=5.0` 使得采样值偏向低值，更接近 `center`
3. **噪声**：高斯噪声 `N(0, 0.02)` 增加真实感
4. **裁剪**：确保最终值在 `[0.0, 1.0]` 范围内

#### 4.2.3 `_smooth_loads()` - 平滑处理

```python
def _smooth_loads(self, loads: np.ndarray, timestamps: List[datetime]) -> np.ndarray:
    """平滑负载数据（避免跳变）"""
    if self.advanced.smoothing_method == "linear_interpolation":
        # 使用移动平均
        window_size = max(1, self.advanced.smoothing_window_minutes // 
                        self.global_cfg.time_interval_minutes)
        
        smoothed = np.copy(loads)
        for i in range(len(loads)):
            start_idx = max(0, i - window_size // 2)
            end_idx = min(len(loads), i + window_size // 2 + 1)
            smoothed[i] = np.mean(loads[start_idx:end_idx])
        
        return smoothed
    return loads
```

**平滑参数**：
- `smoothing_window_minutes = 15` （默认）
- `time_interval_minutes = 5` （默认）
- 窗口大小 = 15 / 5 = 3 个时间步
- 每个点取前后各1.5个时间步的平均值

#### 4.2.4 `_apply_gnb_variation()` - 基站差异化

```python
def _apply_gnb_variation(self, loads: np.ndarray, gnb_id: int) -> np.ndarray:
    """应用基站差异化"""
    if gnb_id == 0:
        multiplier = 1.05   # 中心基站，负载略高 +5%
    elif gnb_id == 2:
        multiplier = 0.95   # 边缘基站，负载略低 -5%
    else:
        multiplier = 1.0    # 基站1，负载正常
    
    adjusted = loads * multiplier
    return np.clip(adjusted, 0.0, 1.0)
```

## 5. **时间关联性分析** ⭐

### 5.1 时间步 t1 与 t2 之间的关联关系

这是理解数据生成机制的核心问题。我们从以下几个角度分析：

#### 5.1.1 **原始生成阶段（平滑前）**

在**平滑处理之前**，每个时间步的负载生成是**相对独立**的：

```python
# 每个时间步 t 的负载生成
load[t] = center[hour(t)] + (max[hour(t)] - center[hour(t)]) * Beta(2, 5) + Noise
```

**关键特征**：
1. **基于当前时刻**：负载仅依赖于当前时间 `t` 的小时值
2. **随机采样**：每次调用 `np.random.beta()` 和 `np.random.normal()` 产生独立随机值
3. **无记忆性**：不考虑前一个时间步 `t-1` 的负载值

**结论**：在此阶段，`load[t1]` 和 `load[t2]` 之间**没有直接关联**（除非 t1 和 t2 处于同一2小时时段，共享相同的 center/max 配置）。

#### 5.1.2 **平滑处理阶段**

在**平滑处理之后**，引入了**时间关联性**：

```python
# 移动平均平滑
smoothed[t] = mean(loads[t - window/2 : t + window/2])
```

**窗口大小**（默认配置）：
- `smoothing_window_minutes = 15 分钟`
- `time_interval_minutes = 5 分钟`
- `window_size = 3 个时间步`

**示例**：
假设原始负载序列为 `[0.4, 0.6, 0.5, 0.7, 0.6]`（时间步 t=0,1,2,3,4）

对于 `t=2` 时刻的平滑：
```
smoothed[2] = mean(loads[1:4]) = mean([0.6, 0.5, 0.7]) = 0.6
```

**关联性分析**：

| 时间步间隔 | 是否关联 | 关联强度 | 说明 |
|-----------|---------|---------|------|
| t2 = t1 | ✅ 强关联 | 100% | 同一时间步 |
| t2 = t1 ± 1 | ✅ 强关联 | 高 | 滑动窗口重叠（窗口大小=3） |
| t2 = t1 ± 2 | ⚠️ 弱关联 | 中 | 窗口边缘重叠 |
| t2 = t1 ± 3 | ❌ 无关联 | 无 | 窗口不重叠 |

**数学表达**：

对于时间步 t1 和 t2，它们的平滑后负载的关联性取决于窗口重叠：

```
如果 |t2 - t1| <= window_size，则 smoothed[t1] 和 smoothed[t2] 存在关联
关联权重 ≈ max(0, 1 - |t2 - t1| / window_size)
```

**示例计算**（window_size = 3）：
- `t1 = 10, t2 = 11`：窗口 [9,10,11] 和 [10,11,12]，重叠2个时间步，**关联性强**
- `t1 = 10, t2 = 12`：窗口 [9,10,11] 和 [11,12,13]，重叠1个时间步，**关联性中**
- `t1 = 10, t2 = 13`：窗口 [9,10,11] 和 [12,13,14]，无重叠，**无关联**

#### 5.1.3 **同一时段内的关联**

即使不考虑平滑，处于**同一2小时时段**的时间步会共享相同的配置参数：

```python
# 例如：t1 = 8:00, t2 = 9:00，都属于时段 "8-9"
load[t1] ~ center=0.45 + (0.65-0.45) * Beta(2,5) + Noise
load[t2] ~ center=0.45 + (0.65-0.45) * Beta(2,5) + Noise
```

**统计关联**：
- 期望值相近：`E[load[t1]] ≈ E[load[t2]]`（因为共享 center/max）
- 但仍有随机性：由于独立的随机采样，具体值可能不同

## 6. **基站关联性分析** ⭐

### 6.1 不同基站负载之间的关联关系

#### 6.1.1 **生成独立性**

在数据生成过程中，**每个基站的负载是独立生成的**：

```python
# 为每个基站独立调用
for gnb_id in range(n_gnbs):
    loads = self._generate_gnb_loads(timestamps, gnb_id)  # 独立生成
    gnb_loads.append(loads)
```

**关键点**：
1. 每个基站使用**独立的随机采样**
2. 没有基站间的耦合机制
3. 即使在同一时刻 t，`gnb_0_load[t]`、`gnb_1_load[t]`、`gnb_2_load[t]` 也是独立生成的

#### 6.1.2 **唯一的关联：基站差异化**

唯一的基站间"差异"来自于**固定的乘数系数**：

```python
# 基站差异化（应用在所有时间步）
gnb_0: multiplier = 1.05  # 负载 +5%
gnb_1: multiplier = 1.00  # 负载 不变
gnb_2: multiplier = 0.95  # 负载 -5%
```

**性质分析**：
- 这是一个**确定性变换**，不是随机关联
- 导致基站0的整体负载水平略高于基站2
- 但不同基站在**同一时刻的相对变化**仍然是独立的

**示例**：
```
时刻 t=100:
  原始 gnb_0[100] = 0.60  →  调整后 = 0.60 × 1.05 = 0.63
  原始 gnb_1[100] = 0.55  →  调整后 = 0.55 × 1.00 = 0.55
  原始 gnb_2[100] = 0.62  →  调整后 = 0.62 × 0.95 = 0.589

时刻 t=101:
  原始 gnb_0[101] = 0.50  →  调整后 = 0.50 × 1.05 = 0.525
  原始 gnb_1[101] = 0.70  →  调整后 = 0.70 × 1.00 = 0.70
  原始 gnb_2[101] = 0.48  →  调整后 = 0.48 × 0.95 = 0.456
```

可以看到，虽然基站0整体偏高，但具体时刻的大小关系是随机的（t=100时 gnb_0 > gnb_2，t=101时 gnb_1 > gnb_0 > gnb_2）。

#### 6.1.3 **隐式关联：共享时间特征**

所有基站共享相同的**时间特征**（日期档位、时段配置）：

```python
# 所有基站在同一时刻使用相同的 date_profile 和 hour_segment
for gnb_id in [0, 1, 2]:
    profile = get_date_profile(current_date)      # 相同
    config = profile.get_load_for_hour(hour)      # 相同
    center, max = config['center'], config['max'] # 相同
```

**统计关联**：
- 所有基站在同一时刻的负载**期望值相近**
- 宏观趋势一致（如都在早高峰时段偏高）
- 但微观波动独立（由于独立的随机采样）

---

## 7. 关联性总结

### 7.1 时间维度关联性

| 关联类型 | 是否存在 | 强度 | 机制 |
|---------|---------|------|------|
| **同一时间步** (t1 = t2) | ✅ 是 | 100% | 同一数据点 |
| **相邻时间步** (Δt = 5分钟) | ✅ 是 | 高 | 平滑窗口重叠 |
| **近邻时间步** (Δt = 10-15分钟) | ⚠️ 弱 | 中 | 平滑窗口边缘重叠 |
| **远距时间步** (Δt > 15分钟) | ❌ 否 | 无 | 窗口不重叠，独立生成 |
| **同一时段** (同属"8-9"等) | ⚠️ 统计 | 低 | 共享配置参数 |

### 7.2 空间维度关联性（基站间）

| 关联类型 | 是否存在 | 强度 | 机制 |
|---------|---------|------|------|
| **直接关联** | ❌ 否 | 无 | 独立随机生成 |
| **确定性差异** | ✅ 是 | 弱 | 固定乘数 (1.05, 1.0, 0.95) |
| **宏观趋势一致** | ✅ 是 | 中 | 共享时间特征 |
| **微观波动** | ❌ 否 | 无 | 独立随机采样 |

### 7.3 可视化理解

```
时间维度关联性：
  t1     t2     t3     t4     t5     t6
  |------|------|------|------|------|
  [====窗口1====]
         [====窗口2====]
                [====窗口3====]
                       [====窗口4====]
  
  → t1 和 t2 关联（窗口重叠）
  → t1 和 t4 不关联（窗口不重叠）

基站维度关联性：
  gnb_0: [0.63, 0.52, 0.58, ...] ×1.05
  gnb_1: [0.60, 0.50, 0.55, ...] ×1.00
  gnb_2: [0.59, 0.47, 0.52, ...] ×0.95
         ↑     ↑     ↑
      独立生成（无关联）
      但共享时间特征（宏观趋势相似）
```

```csv
timestamp,gnb_0_load,gnb_1_load,gnb_2_load

```

### 8.2 数据统计特性

以90天数据为例（时间间隔5分钟）：
- **总记录数**：90 × 24 × 60 / 5 = 25,920 条
- **数据量**：约 2-3 MB（CSV格式）
- **时间跨度**：90天（约3个月）

**负载分布**：
- 平均值：约 0.35 - 0.45（取决于日期分布）
- 最小值：接近 0.08（深夜凌晨）
- 最大值：1.0 - 1.2（极端高峰，如除夕看春晚、春节跨年）
  - 普通场景：< 1.0
  - 超载场景：1.0 - 1.2（除夕18-23点、春节0-1点）

## 11. 优化与扩展

### 11.1 性能优化

#### 当前性能
- **90天数据生成时间**：约 5-10 秒（3个基站，25920条记录）
- **内存占用**：约 50-100 MB

#### 优化建议
1. **向量化计算**：使用 NumPy 批量操作替代循环
2. **并行生成**：多进程同时生成多个基站数据
3. **缓存配置**：避免重复解析 YAML 文件

### 11.2 功能扩展

#### 11.2.1 增强基站关联性

当前基站负载是独立生成的，可以引入**空间相关性**：

```python
# 伪代码：基于距离的相关性
def generate_correlated_loads(gnbs, correlation_matrix):
    # 使用多元正态分布
    mean = [base_load] * len(gnbs)
    cov = correlation_matrix * variance
    loads = np.random.multivariate_normal(mean, cov)
    return loads
```

**相关性矩阵示例**：
```
       gnb_0  gnb_1  gnb_2
gnb_0 [1.00   0.60   0.30]
gnb_1 [0.60   1.00   0.60]
gnb_2 [0.30   0.60   1.00]
```

#### 11.2.2 增强时间关联性

引入**马尔可夫性质**（当前时刻依赖前一时刻）：

```python
# 伪代码：AR(1) 模型
def generate_with_memory(base_loads, alpha=0.3):
    loads = [base_loads[0]]
    for i in range(1, len(base_loads)):
        # 30% 继承前一时刻，70% 来自新采样
        load = alpha * loads[-1] + (1-alpha) * base_loads[i]
        loads.append(load)
    return loads
```

#### 11.2.3 添加突发事件

模拟偶发的流量突发：

```python
# 伪代码：随机突发
def add_bursts(loads, burst_prob=0.01, burst_magnitude=0.3):
    for i in range(len(loads)):
        if np.random.random() < burst_prob:
            loads[i] = min(1.0, loads[i] + burst_magnitude)
    return loads
```

## 12. 常见问题 (FAQ)

### Q1: 为什么使用 Beta 分布？

**A**: Beta(2, 5) 分布的特性：
- 定义域 [0, 1]，适合生成百分比值
- 参数 alpha=2, beta=5 使得分布**偏向低值**
- 大约 70% 的采样值落在 [0.1, 0.4] 区间
- 符合"大部分时间负载偏低，偶尔高负载"的真实模式

### Q2: 平滑窗口如何选择？

**A**: 考虑因素：
- **太小**（如5分钟）：几乎无平滑效果，数据波动大
- **太大**（如60分钟）：过度平滑，丢失细节信息
- **推荐**：15-30分钟（3-6个时间步），平衡平滑与细节

### Q3: 如何验证生成的数据质量？

**A**: 验证清单：
1. ✅ 时间连续性（无缺失时间步）
2. ✅ 值域范围（[0, 1]）
3. ✅ 日期档位正确性（节假日识别）
4. ✅ 时段峰值合理性（早晚高峰明显）
5. ✅ 基站差异性（基站0 > 基站1 > 基站2，宏观趋势）
6. ✅ 平滑度（无剧烈跳变）

### Q4: 数据可复现性如何保证？

**A**: 通过**固定随机种子**：
```python
np.random.seed(42)  # 全局固定
```
相同的种子 + 相同的配置 = 完全相同的数据。

### Q5: 如何模拟特殊场景（如网络故障）？

**A**: 手动修改配置或后处理：
```python
# 后处理：模拟基站2在第10-20天故障
df.loc[(df['timestamp'] >= '2025-01-10') & 
       (df['timestamp'] < '2025-01-20'), 'gnb_2_load'] = 0.0
```

## 13. 总结

### 13.1 核心设计思想

1. **配置驱动**：所有参数可通过 YAML 文件灵活配置
2. **分层设计**：日期档位 → 时段配置 → 随机采样 → 平滑处理
3. **可复现性**：固定随机种子，保证实验可重复
4. **真实性**：模拟7种日期类型，覆盖工作日、节假日、周末等场景

### 13.2 关联性总结（核心答案）

#### 时间维度
- ✅ **相邻时间步强关联**（通过平滑窗口，窗口大小约3个时间步）
- ⚠️ **远距时间步弱关联**（超过窗口范围后独立）
- ⚠️ **同一时段统计关联**（共享配置参数，但具体值独立采样）

#### 空间维度
- ❌ **基站间无动态关联**（独立随机生成）
- ✅ **基站间有固定差异**（通过乘数系数：1.05, 1.0, 0.95）
- ✅ **基站间宏观趋势一致**（共享时间特征，如都在早高峰时负载高）

### 13.3 适用场景

✅ **适合**：
- LSTM/Transformer 序列预测模型训练
- 负载均衡策略对比实验
- 网络容量规划仿真
- 算法性能基准测试

⚠️ **限制**：
- 不适合需要强空间相关性的场景（如基于地理位置的流量扩散）
- 不适合需要复杂随机过程的场景（如马尔可夫链、泊松过程）
